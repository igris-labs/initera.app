The issue detail separates its content from its properties. Use **Edit issue** for the title, description, and dates. Select a property value directly for status, priority, project, estimate, or labels.

![Issue editor with title, description, dates, and save state](/images/app/edit-issue.png)

## Edit the title or description

1. Open the issue from **All issues**, a board card, or a search result.
2. Select **Edit issue** in the detail header, or press **E** while the issue is open.
3. Change the title or description. Use the date controls in the same editor if the plan changed.
4. Select **Save changes**. Wait for **Saved** before you close the editor.

The title should identify the work in a list. Use the description for steps, expected behavior, decisions, links, or acceptance checks. A long description is useful when all parts share one status; use sub-issues when they need separate progress.

## Format the description

The editor supports paragraphs, headings, lists, checklists, code, links, and images. Select text to format it from the toolbar. Type `/` in an empty block to open block commands.

Paste or add an image when a visual explains the work better than text. The desktop app stores uploaded images in its media folder and keeps references in the issue. A local backup or portable export includes those files. If an image file is missing, the editor shows a placeholder instead of a blank area.

## If a save fails

The editor keeps a recovery draft for content that has not reached storage. If the save state says **Not saved**, select **Retry save**. Leave the editor open until the state changes to **Saved**, or keep the recovery draft and return later. The app asks about pending content writes when you close it.

A recovery draft is separate from the last saved issue. Another view may still show the saved version until the pending write succeeds. Do not discard the recovery draft until you have checked the result.

## Add or change a comment

1. Scroll to **Activity** on the issue.
2. Enter a comment in **Write a comment**.
3. Select **Post comment**. The comment appears in the timeline with your name and the time.
4. Select **Edit** beneath your comment to revise it, then **Save comment**. Select **Delete** and confirm to remove its text.

Deleted comments leave a “Comment deleted” entry in the timeline. The timeline also records changes to the issue's status and other properties. Select **Load older activity** when the first page does not reach the entry you need.

## FAQ

### Does a property change need Save changes?

No. Property pickers save the selected value. **Save changes** applies to the issue content editor.

### Can I restore the text of a deleted comment?

The timeline records that a comment was deleted, but its text is not shown there. Check a backup if you need an earlier copy.

### Why do I see “Not saved” after editing?

The write failed or has not finished. Select **Retry save** and wait for **Saved**. The recovery draft keeps the unsaved content while you resolve the failure.
