An issue is one piece of work with its own identifier, status, description, and history. This page maps the issue lifecycle. For a step-by-step task, open [Create an issue](/issues/creating-issues), [Issue properties](/issues/issue-properties), or [Edit issue content](/issues/editing-issues).

## Create an issue

Select **Create issue** in the top right, or press **C** outside an editor. Enter a title that describes one piece of work. Add a description when someone needs steps, a decision, or a link to continue.

The composer lets you choose status, priority, estimate, project, milestone, labels, start date, and due date. You can leave these fields empty except for the title. If you set dates, the due date must fall on or after the start date. A draft survives an interrupted composer session, so you can return to unfinished text.

![Create issue dialog with property pills and description editor](/images/app/create-issue.png)

Select **Create issue** to save. Turn on **Create more** before saving if you want to enter another issue without reopening the dialog. The app assigns an identifier at creation. Issues in a project use that project's identifier prefix.

## Open and change an issue

Select a row in **All issues** or a card on the board. The preview shows the title, description, properties, related work, activity, and time. Select **Open full issue view** when you need more space.

![Issue detail with description, relations, and properties](/images/app/issue-detail.png)

Select a property pill in the right panel to change status, priority, project, estimate, parent, or labels. The picker shows the current choice with a check mark. Select **Edit issue** to change the title, description, start date, or due date. Save the edit with **Save changes**; use **Cancel** to leave the saved content as it was.

If a content write fails, use **Retry save**. The editor keeps a recovery draft for text that has not reached storage. The app asks about pending writes when you close it; review that prompt before you discard text.

## Set status and priority

Your workspace workflow defines the status names and their board columns. A status can belong to the backlog, planned, started, completed, or canceled part of the workflow. You can change a status from the issue panel, list context menu, or board drag.

Priority choices are **No priority**, **Low**, **Medium**, **High**, and **Urgent**. Priority affects how you sort or filter work; it does not change the issue's status. On an open issue, press **S** for status or **P** for priority.

If your team needs another status, open **Settings → Workflow statuses**. Read [Settings](/reference/settings) before you archive a status that issues use.

## Assign project, milestone, and labels

Select **Project** to attach the issue to a project. After you choose a project, select a milestone from that project's milestones if the issue belongs to one stage. A milestone only accepts issues from its project.

When you move an issue between projects, the app may ask whether to keep its identifier or give it the destination project's prefix. **Settings → Issue moves** controls this choice. Read the dialog before you confirm: references to an identifier may matter to people who use it outside the app.

Use labels for categories that cut across projects, such as “Bug” or “Design.” You manage the workspace label list in Settings. Archived labels leave the active picker but remain recoverable.

## Estimate and schedule work

Select **Estimate** to assign a size. The workspace estimate scale sets the labels you see: points, sizes, or time units. Changing scales does not rewrite estimates already stored on issues.

Use **Start date** for the planned beginning and **Due date** for a deadline. A date filter can find work in a chosen period. For effort you have already spent, use [Time tracking](/planning/time-tracking); an estimate and a time entry answer different questions.

## Write a description

The description editor supports paragraphs, headings, lists, checklists, code, links, and images. Select text to format it with the toolbar. Type `/` in an empty block to see available block commands. An uploaded image lives in the app's media folder; a backup includes it.

Keep the title short enough for the issue list. Put acceptance checks, reference links, and notes in the description. If you need independent progress or a separate owner, create a sub-issue instead of a long checklist. Read [Sub-issues and relations](/issues/issue-relations).

## Discuss changes

Write in **Activity → Write a comment** and select **Post comment**. You can edit a comment or delete it from its own controls. The timeline also records status and property changes with the actor and time. Use **Load older activity** to see entries beyond the first page.

The **Time tracked** section sits on the issue. Start a timer there or add a manual entry with a date, start time, duration, and note. The workspace Time page collects entries from all issues.

## Find and organize issues

**All issues** offers **Active** and **All** scopes, list and board layouts, filters, grouping, and display options. You can drag a board card to another group or reorder it within a group. On the list, use the context menu for actions without opening the issue.

![All issues list with status groups and display controls](/images/app/issues-list.png)

Use [Views and search](/planning/views-and-search) when you need a saved filter or a different set of columns. Use [Triage and archive](/issues/triage-and-archive) to accept incoming work, archive completed context, or restore an issue.

## FAQ

### Why is an issue absent from Active?

**Active** omits completed and canceled work. Switch to **All**, check the current filters, or search by identifier in the command bar. Archived issues appear under **Archives**.

### Can one issue belong to more than one project?

No. An issue has one project assignment at a time. Use labels and relations to connect work across project boundaries.

### When should I make a sub-issue?

Create a sub-issue when a part of the work needs its own status, comments, estimate, or time entries. Keep a checklist in the description for steps that share the parent issue's progress.
