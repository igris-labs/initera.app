## Start and pause a timer

Open an issue and find **Time tracked** below its activity. Select **Start timer** when you begin work. The issue shows a running total. Select **Pause timer** when you stop; the saved entry then appears in the issue's time list.

If another issue has a running timer and your workspace allows only one, the app asks whether to pause that timer and start this one. Select **Switch timer** to confirm. You can allow timers on different issues to run together in **Settings → Time tracking**.

## Enter work after the fact

Select **Add time** on the issue. Choose the entry date and local start time, then enter hours, minutes, and seconds. Add an optional note that tells you what the time covered. Select **Save time**.

The form shows your time zone. If a daylight saving change makes a local time occur twice, choose **Earlier occurrence** or **Later occurrence**. Leave the default when the date has no overlap.

If the entry overlaps another recorded interval, the app shows an **Overlapping time** dialog. Review the existing entry before you select **Save anyway**: totals include both intervals.

## Correct an entry

Use the pencil control beside a stopped entry to change its date, time, duration, or note. Select **Save changes** when the correction is ready. Use the trash control to remove an entry you added to the wrong issue. The app retains a removal record for its activity and recovery history.

You cannot edit a running entry. Pause its timer first, then use the entry controls.

## Review work across the workspace

Select **Time tracking** in the workspace navigation, or press **G** then **L**. The page groups entries by day. Each row shows its issue, project, note, and duration. Select the issue link to return to the work record.

Use the **Issue** and **Project** fields to narrow the list. Set **From date** and **Through date** for a period. The total and entry count follow the filters. Select **Load more entries** to reach older rows, or **Refresh time** after a change on another screen.

## Choose timer policies

Open **Settings → Time tracking** in the installed app:

| Setting                                       | Choice                                                                          |
| --------------------------------------------- | ------------------------------------------------------------------------------- |
| On exit                                       | Pause at the last saved checkpoint, or include time while the app stays closed. |
| Concurrent timers                             | Allow timers on different issues to run together, or keep one running timer.    |
| While the app is open and the computer sleeps | Pause the timer, or include the sleeping period.                                |

If you turn off concurrent timers while several run, choose which issue keeps its timer or pause all of them. **Continue after exit** includes closed time and sleep. Pause the timer before closing the app if that time should not count.

## Review time after a long gap

On restart, the app may ask you to review a timer after a long closed period or a clock change. Check the dates and duration before you accept the elapsed time. If the app paused a timer at its last checkpoint after a crash, add a manual entry for work that the checkpoint missed.

## FAQ

### Why did another timer pause when I started one?

The workspace may be set to keep one running timer. Open **Settings → Time tracking** to choose whether timers on different issues can run together.

### Why does the total seem too high?

Check for overlapping manual entries or concurrent timers. Open the day in **Time tracking**, filter by issue if needed, and edit or remove the incorrect entry.

### Can I change a running entry?

Pause it first. The edit control then lets you correct its date, start time, duration, and note.
