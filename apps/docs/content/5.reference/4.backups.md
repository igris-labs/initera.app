## Open the backup controls

Open **Settings → Backups** in the installed desktop app. The section lists saved backups by creation time and size. You can create a backup in the app data folder, export one of those backups, or export the current workspace as a portable ZIP.

## Create a local backup

Select **Create backup**. Wait for the **Backup created** notification, then check that a new row appears in the list. The snapshot contains the SQLite workspace data and its managed images. Use this option before an import, a large cleanup, or a project lifecycle change that affects many issues.

A local backup stays inside the app data folder. If you lose that folder or the computer, the backup goes with it. Export a copy to another location when you need protection from that loss.

## Export a file

Use one of these actions:

| Action                       | File you receive                                           |
| ---------------------------- | ---------------------------------------------------------- |
| **Export workspace**         | A portable ZIP of the current workspace and managed media. |
| **Export** on a saved backup | A ZIP of that backup as it existed when you created it.    |

Choose the destination in the file picker. The app shows **Saved to** with the path after export; select **Copy path** if you need to locate the file. Wait for the export notification before you copy or move it.

Both exports include referenced images. Copying `workspace.sqlite` alone from the data folder does not carry the media files.

## Import a workspace

Select **Import** and choose a supported `.zip` or `.sqlite` file. The app inspects the file before changing the current workspace. The review dialog shows the source workspace name and counts for projects, issues, cycles, and images.

Check the name and counts, then select **Import workspace**. Import replaces the current workspace and restarts the app. The app keeps a recovery copy of the data it replaces. Select **Cancel** if you chose the wrong file; canceling the review leaves the current workspace in place.

The picker accepts ZIP files up to 550 MB and SQLite files up to 100 MB. If your file exceeds the limit, reduce its size or move the data by another supported export path before importing.

## Restore a saved backup

Select **Restore** on a backup row. The dialog names the snapshot date and warns that the app will restart and replace current data. Confirm **Restore backup** only after you have checked that date. The app keeps a recovery copy in its data folder during the restore.

After the restart, check the workspace name, recent issues, and uploaded images. The app reconciles cycle schedules after import or restore. If it reports a restore failure, the previous data remains available; read the error before you try again.

## Keep a copy you can find

Save an exported ZIP outside the application data folder, such as an external drive. Give the file a name or location that identifies its date and source workspace. Open the export location after saving to confirm the file exists. Keep the archive private if project descriptions, comments, or images contain sensitive work.

## FAQ

### Which option gives me a file I can keep outside the app?

Choose **Export workspace** for the current data, or **Export** on a saved backup for that snapshot. **Create backup** keeps its copy inside the app data folder.

### Does a backup include uploaded images?

Yes. The app's backup and portable export paths include managed images. A copied SQLite file by itself does not include media files.

### Can I inspect an import before replacing data?

Yes. Choose the file and read the review dialog's workspace name and record counts. Select **Cancel** to leave the current workspace in place.
